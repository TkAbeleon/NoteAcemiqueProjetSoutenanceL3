# Guide de démonstration — JeryMotro

## Avant le rendez-vous

> [!check] Checklist
> - [ ] Tester l’URL de démonstration
> - [ ] Vérifier que l’API répond
> - [ ] Préparer une connexion Internet de secours
> - [ ] Préparer 2 ou 3 captures d’écran au cas où le live échoue
> - [ ] Vérifier que les données visibles sont compréhensibles
> - [ ] Ne pas dépendre d’une fonctionnalité encore instable

## Ordre conseillé

### 1. Accueil

Dire en une phrase ce qu’est JeryMotro.

### 2. Carte

Montrer immédiatement le résultat visuel.

À dire :

> « Ici, on peut visualiser les informations de détection sur le territoire. »

### 3. Détection / événement

Choisir un exemple compréhensible et montrer les informations disponibles.

À dire :

> « Plusieurs observations peuvent être regroupées pour représenter un événement plutôt que de considérer chaque point isolément. »

### 4. Analyse / risque

Montrer le score ou indicateur réellement disponible.

À dire :

> « Le score sert à prioriser l’analyse ; il ne constitue pas une confirmation terrain. »

### 5. Statistiques

Montrer les indicateurs disponibles.

### 6. Chat IA

Si le service est disponible, poser une question simple portant sur les données du projet.

> [!warning] Éviter
> Une question dont la réponse dépend d’informations qui ne sont pas réellement présentes dans la base ou le RAG.

### 7. Alertes

Montrer la logique de configuration si elle est disponible, sans déclencher une vraie alerte devant la Ministre sauf si cela a été préparé et sécurisé.

## Plan B

Si Internet ou le serveur échoue :

1. montrer une capture de la carte ;
2. montrer une capture d’un événement ;
3. expliquer le pipeline ;
4. présenter les résultats déjà validés ;
5. expliquer honnêtement ce qui nécessite encore une validation.

## Règle d’or

> **La démonstration doit montrer le résultat avant la technologie.**
